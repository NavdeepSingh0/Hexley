| D-026 | 2026-10-27 | **Audit log as built.** Records: `contract.issued` (the officer's confirmation, the first record of a session), `decision` (before anything is forwarded), `result` (hash and size only), `freeze`. Arguments are stored as a hash plus argument names; matched secret values are removed from decision evidence (a hash of a four-digit number is guessable, so values are dropped, not hashed). | D-036 | 2026-10-27 | **OAuth sign-in as built (core plan B1).** `src/sentinel/oauth.py` subclasses FastMCP's `OAuthProvider` (registration, PKCE, discovery and the token endpoint come from the library). `/authorize` approves nothing: it parks a request with a random six-digit **officer code** shown only in the terminal and event bus, and sends the browser to a consent page on the gateway. Only the right code confirms the slip (through the same `confirm.confirm_draft` that mints every session) and issues a one-time authorization code; five wrong codes lock the request; requests and codes expire. **The access token is our signed session token**, so the middleware is unchanged and the header route still works. Access tokens last at most 15 minutes and never longer than the slip. **A refresh re-issues a token for the same session** (`mint_session_token(session_id=...)`), because a new session would reset the message budget, the block counter and the fingerprints; it is refused once the session is frozen or the slip's own expiry has passed (the slip expiry was previously not enforced beyond the first token). Refresh tokens rotate and are bound to their client. OAuth is opt-in (`up --public-url URL` or `--tunnel`); without it the gateway behaves exactly as before. At the HTTP layer a token is checked for signature, audience and expiry only; frozen sessions are answered by the middleware with a clear message instead of a bare 401. **Known behaviours, stated rather than hidden:** (1) a wrong PKCE verifier is refused (`401 invalid_grant`) but does not burn the code, which is library behaviour; the verifier is a random secret, so guessing it is not feasible; (2) a quarantined session that tries to *list* tools gets a generic "Internal server error", while a tool *call* gets the clear message; (3) the consent page is reachable over the tunnel and protected only by the officer code plus the attempt limit; (4) the revocation endpoint is disabled, so disconnecting simply lets the token lapse; (5) the slip an OAuth sign-in approves is a fixed preset (quotation, work item Q-1043) until the slip builder (B2); (6) state is in memory and there is one demo officer: demo-grade, not production identity management. **Verified live** on 27 Oct 2026 with a free Claude.ai account through a cloudflared tunnel: Claude detected "Sign in now" and automatic registration, the officer approved with the code, and a send containing stock figures was denied (R2) with nothing delivered; the audit chain verified.
