# Mascot contract

The art and the widget are the team's (frontend plan, phase A6). **When** the mascot changes state is decided by the backend from real events (core plan, phases B5 and B7), so the mascot never shows something that did not happen.

## Widget
`site/public/mascot/sentinel-mascot.js`: a framework-free Web Component registered as `sentinel-mascot`. It lives in `public/` (served as-is, no build step) so the console, the extension and a plain HTML page can load the same file; React pages load it with a `<script type="module">` tag in `site/index.html`.

```html
<script type="module" src="/mascot/sentinel-mascot.js"></script>
<sentinel-mascot state="idle" message="" size="64" theme="dark"></sentinel-mascot>
```

| Attribute | Values | Behaviour |
|---|---|---|
| `state` | `sleeping`, `idle`, `checking`, `allowed`, `denied`, `needs-approval`, `quarantined`, `verified`, `tamper` | plays that state's animation; unknown values fall back to `idle` |
| `message` | text, max 90 characters | speech bubble; hides after 6 s except in `quarantined` and `needs-approval` |
| `size` | `64` (default) or `128` | rendered size in CSS pixels, crisp (`image-rendering: pixelated`) |
| `theme` | `dark` (default) or `light` | bubble colours; the sprite itself must read on both |
| `speak` | present or absent | when present, reads `message` aloud with `speechSynthesis` (off by default) |
| `sprites` | URL of the folder holding `mascot.json` (default `/mascot/`) | lets the console and the extension point at their own copy |

Rules: no network requests except its own sprite files; `prefers-reduced-motion: reduce` shows the first frame only; works in plain HTML with no build step.

## Art (revised 28 Oct 2026: vector, not pixel sprites)
The mascot is an inline **SVG drawn and animated by the component itself** (CSS keyframes), so motion is fluid (squash and stretch, blinking, eye scanning, shake) and it is crisp at any `size`. There are no sprite sheets, no `mascot.json` and no image files; the `sprites` attribute and `image-rendering: pixelated` above no longer apply, and `size` may be any pixel value (default 64).

Character (agreed with Navdeep, 28 Oct 2026): an original **rounded screen-cube robot**, front-facing. Glossy white soft-cornered body with a dome highlight on top, a dark rounded screen with a faint pixel grid and two blocky eyes, a small dark badge tile at the bottom right whose dot takes the decision colour, a short vent line at the bottom left, a soft shadow underneath. (The retro monitor with an angled side was tried first and set aside: Navdeep chose the cube, which also animates more simply.) Inspired by the proportions and mood of Navdeep's reference images; **not** copied (no caret badge or other brand mark), not a Supercell character, not Claude's mascot.

Rules for the art:
- The screen is always dark, so face colours are fixed bright values (white, violet, green, blue, amber) in both page themes; only the body and the shadow follow the theme.
- No red on the body. The tamper state may use the `--harm` red on the screen only.
- Quarantined inverts the body (black body, white screen) so it reads as a different object, not just a colour change.
- A state only changes the face, the badge dot and a small motion; the body shape never changes between states.
- `prefers-reduced-motion: reduce` stops all animation (static frame).
- Prototype: scratch file `mascot_proto/index.html`, reviewed in both themes on 28 Oct 2026.

## Event → state (owned by the backend)
| Real event | State | Holds |
|---|---|---|
| no active session | `sleeping` | until a session starts |
| session started | `idle` | default |
| an action is requested | `checking` | until its decision |
| decision ALLOWED | `allowed` | 1.5 s, then `idle` |
| decision DENIED | `denied` | until the next action |
| decision NEEDS APPROVAL / approval pending | `needs-approval` | until approved, denied or expired |
| decision QUARANTINED (freeze) | `quarantined` | for the rest of the session |
| audit log verified intact | `verified` | 3 s |
| audit log found altered | `tamper` | until verified again |

## Speech (templated from the rule that decided; never generated by an AI)
| Rule | Message |
|---|---|
| R1 | That's not on the permission slip. |
| R2 | That would send restricted data out. |
| R3 | That address came from an untrusted document. |
| R4 | This needs the officer's approval. |
| R5 | Message limit reached. |
| R6 | Too many denied attempts: quarantined. |
| R7 | After an untrusted document, sending outside needs approval. |
| ALLOWED | Checked: allowed. |
| verified | Audit log intact. |
| tamper | The audit log was altered! |
